Supply Chain Impact Analysis Platform

.NET 10 · PostgreSQL + Neo4j · Clean modular solution

The Continuity Question

If a supplier becomes unavailable, which products, warehouses, and stores depend on that supplier? One call to the impact endpoint answers it by traversing the supply network graph.

✅ Implemented
  • ✔ Relational supply-chain model (suppliers, products, warehouses, stores)
  • ✔ EF Core migrations + sample data seeding
  • ✔ REST endpoints for all main entities
  • ✔ GET /api/suppliers/{id}/impact via Neo4j traversal
  • ✔ Swagger / OpenAPI docs in Development
🔮 Planned
  • ◷ Alternative supplier discovery & pathfinding
  • ◷ Subgraph queries
  • ◷ Incremental graph synchronization
  • ◷ Redis caching for impact results
  • ◷ RabbitMQ + MassTransit event processing
  • ◷ Auth, health checks & automated tests
📦 Example Scenario — Acme Electronics

Sample data includes Acme Electronics, Globex Components, and Initech Materials; three products; two distribution centers; and three stores. Acme supplies Microchip A1 and PCB Board X, stocked across North DC and South DC, which together serve Store A, B, C.

The endpoint reports dependency paths and the supplier's active status — it does not calculate replacement routes or automatically reroute supply.

🔗 How the Model Works

Supplier-product contracts, warehouse stock, and warehouse-store service areas are modeled as separate relationships carrying their own data — contract prices, stock quantities, reorder thresholds, and service priorities. For each impact request, the API reads the current model from PostgreSQL, refreshes the corresponding nodes and relationships in Neo4j, and traverses the graph. This full refresh keeps the MVP simple; incremental sync is planned for larger networks.

Real-Time Geo-Tracking Application

FastAPI · MongoDB · Redis Pub/Sub · WebSockets · Folium

The Proof of Concept

Create a package with origin & destination coordinates → get an OSRM-optimized route with intelligent intermediate branches → watch the 🚚 move in real time on a live Folium map. No page refreshes, ever.

✨ Features — All Implemented
  • ✔ Real-Time Location Updates — track package movements on a live map via WebSockets, zero page refreshes
  • ✔ Dynamic Route Calculation — optimal driving routes between origin & destination via the OSRM engine
  • ✔ Smart Waypoint Chaining — automatically identifies & includes optimal intermediate company branches to simulate a realistic logistics chain
  • ✔ Interactive Map Visualization — Folium renders the route, branch locations & the package's animated position
  • ✔ Scalable Pub/Sub Architecture — Redis-powered, decoupled publish/subscribe handling of location updates
  • ✔ Asynchronous Backend — FastAPI for high performance & async capabilities
🕹️ How to Use
  • 1. POST your origin/destination coordinates to /packages via curl or Postman
  • 2. Copy the packageId from the response
  • 3. Open /packages/YOUR_PACKAGE_ID/map in your browser
  • 4. Watch the 🚚 icon move along the calculated route in real time!
🔄 Event-Driven Data Flow
📦
1 · Package Creation
Client POSTs origin & destination coordinates to /packages
🗺️
2 · Route Planning
FastAPI calculates the optimal OSRM route + dynamically generated branch chain
🍃
3 · Persistence
Package, route & branch chain stored in a MongoDB collection
🧵
4 · Movement Simulation
Background thread iterates route coords → publishes each location to Redis package_updates
📡
5 · Update Listener
Long-running redis_listener subscribes & fans out: updates MongoDB + broadcasts via WebSocket
🖥️
6 · Live Frontend
Browser map page connects via WebSocket → JS smoothly animates the Folium marker
# The decoupled pipeline Client ──POST /packages──> FastAPI ──> OSRM (route + branch chain) ──> MongoDB │ └── spawns simulate_movement thread │ ▼ Redis · package_updates channel │ ▼ redis_listener ──> update MongoDB │ └──> WebSocket broadcast ▼ Browser (Folium map) <── /ws/{package_id}
Why Decoupled?

The simulator doesn't know about the clients, and the clients don't know about the simulator — Redis Pub/Sub sits between them. This makes it trivial to scale the simulation or add more consumers (analytics, notifications, archiving) without touching the live map.

AddressIntel 📍

.NET 10 · PostGIS · Clean Architecture · CQRS · DDD

Purpose

An enterprise-grade, high-performance geospatial address intelligence engine solving complex challenges in Persian address management, validation, and spatial geocoding.

🎯 Core Capabilities
  • ✔ Persian Address Normalization — Province, City, District, Main/Secondary Street, Alley, Plaque, Postal Code
  • ✔ Domain Invariants — 10-digit postal code regex (^\d{10}$) & Plaque formatting via immutable Value Objects
  • ✔ Spatial Search — PostGIS Point (WGS 84 / SRID 4326) + GiST indexing → O(log N) radius queries
  • ✔ Clean CQRS — Commands & Queries strictly isolated, global NoTracking reads
⚡ Best Practices
  • ◆ EF Core ComplexProperty maps Value Objects to flat columns — no FKs or extra tables
  • ◆ Global QueryTrackingBehavior.NoTracking for low-memory, high-throughput reads
  • ◆ Automatic migrations applied on startup
  • ◆ Global JSON conventions — camelCase, string enums, cycle-safe
🧪 Quality

Backed by an xUnit + FluentAssertions unit test suite covering domain invariants and use-case handlers — the domain layer stays pure with zero outer dependencies.

Inner layers contain pure business logic and have zero dependencies on outer layers. Infrastructure implements the Domain's IPersianAddressRepository contract.

The FindWithinRadius handler queries with NetTopologySuite Points against a GiST-indexed geometry column — turning "find everything within 1 km" into an index seek instead of a full scan.
